Weaver

A privacy-first novel-writing studio that runs entirely in the browser.

2026 Product Live V4 complete
Open app Product site Pricing

The problem

Most writing tools either lock the manuscript into a proprietary cloud or bolt AI onto the side without any notion of what is actually canon. A novelist ends up with the same paragraph in three places, no reliable way to undo an AI suggestion, and a file they cannot leave with. Weaver starts from the opposite assumption: the book is a single source of truth, and nothing enters it without the author's decision.

The bet

  • Local-first. Work is stored in the browser before it is stored anywhere else.
  • Canon-aware AI. Suggestions are grounded in the author's own Config Bible, not the public internet.
  • Own your files. DOCX and EPUB are produced in the browser; the manuscript is never hostage to the tool.
  • Pay once. A lifetime tier sits beside monthly and yearly, sold through Gumroad as merchant of record.

Architecture

In the browser

The app is native ES modules with no framework, no bundler and no build step. A single store emits change flags; feature modules own their panels and inject scoped styles. The text engine, the DOCX and EPUB writers, the cover canvas and the sync client all run locally.

Seventy-two files, twenty directories, about 675 KB uncompressed. Network calls go to Supabase, the AI providers and the optional Puter overflow. Nothing else.

On Supabase

Eight Edge Functions on Deno carry every server-side concern: admin, support, supervisor admin, help, the AI proxy, AI admin and backup. Auth is email and password with custom SMTP; Postgres uses row-level security; the private weaver-vault bucket isolates each user by path policy.

Boundary

The service_role key is auto-injected into functions and never leaves Supabase. Provider keys live in the ai_config table, not in environment variables.

Around it

Groq, OpenRouter, Google Gemini and Mistral sit behind one manager with runtime model discovery. Gumroad is merchant of record; Brevo carries auth and reply email; Resend carries owner-only ledger backups; Puter is the per-user overflow; Cloudflare Pages hosts the marketing site.

The studio site you are reading is separate: a static GitHub Pages project with no backend at all.

Subsystems

Seven pieces where the interesting problems lived. Each one opens.

The block engine and virtualization
What

Raw text stays a string of lines. buildBlockIndex makes one O(n) pass and records {s, e, level, sentences} offsets, never copied substrings. Both editors mount a window of blocks between two spacer divs.

Hard part

Pruning and appending must not move the reader. Spacer heights are computed from scroll-height deltas; the Manuscript keeps a bottom runway and a sticky-bottom pin confirmed on the next frame.

Decision

Render paths never scan text. At rest an editor mounts at most 300 blocks; resume position persists as manuscript.viewStart.

Selection, Recheck and return-to-place
What

Selection is captured on selectionchange into a sticky record, so a button tap or a re-render cannot lose it. In the Main Novel, DOM endpoints are mapped to raw-text character offsets, counting <br> as one newline.

Hard part

A whole-book drag could mount the whole book. Pruning is relaxed while a selection is live but hard-capped at 1,200 nodes, and the text snapshot is taken once, 200 ms after the drag settles.

Decision

Recheck stores a seam of roughly 120 characters on each side of the cut. Return-to-place matches that seam with a whitespace-tolerant expression and restores the original separators; if the seam is gone, the author is told and offered an append.

Config Bible and prompt compilation
What

The bible holds seven sections of canon. Books in a series share one bible, so a sequel inherits the world without re-entry.

Hard part

A 200-entry bible can swallow a context window. compileBible emits standing directives, prose style, entries whose names appear in the context, then a name-only roster of everything else.

Decision

Hard caps: 6,000 characters of compiled bible and 8,000 characters of source context. Relevance is selected before the request is sent, not truncated after.

Cloud sync, compression and failover
What

Project blobs are gzipped in the browser with CompressionStream and stored under {userId}/weaver/ as an index, per-project files and per-series files. Reads sniff the gzip magic bytes and fall back to raw JSON.

Hard part

Sync must never erase work. Manual sync is a two-way merge by updatedAt; deletions propagate through a local ledger of ids known at the last sync. Autosync is debounced three seconds and pushes only the active project, its series bible and a patched index.

Decision

Old v1 blobs stay readable forever with no user-triggered migration. On quota or network failure the client fails over to the author's own Puter account; auth and permission errors surface honestly instead.

The AI layer and model discovery
What

Four provider adapters sit behind one manager. Models are discovered at runtime from each provider's /models endpoint: OpenRouter filtered to zero-priced models, Groq to non-deprecated, Gemini to those supporting generateContent.

Hard part

Providers deprecate and rename constantly. A router scores the discovered models for creative fit and context length rather than trusting a pinned id.

Decision

Zero hardcoded model ids. Pro users are served through a server-side proxy holding the studio's keys; everyone else can bring their own. Streaming is SSE throughout, and admin Diagnostics uses its own keys so debugging never spends customer quota.

Entitlements, payments and the admin console
What

Gumroad sells three products as merchant of record. The admin console provisions access manually; entitlements live in Postgres with row-level security so a user can read only their own row.

Hard part

Selling before webhook code exists. The console is the fulfilment tool: it reads orders, grants Pro and records the action in service-role-only logs.

Decision

Gumroad over Stripe direct at launch, because payout availability for a Kenya-based creator was unresolved and Gumroad handles VAT and invoicing. All server work runs on Supabase Edge Functions so the service key never leaves the platform.

Brand, mobile and the interface system
What

The golden W is drawn as SVG paths and delivered as a CSS background data-URI, shaded with a cross-stroke gradient, a three-pass hairline and a specular bloom. Design tokens live in one base sheet; components, layout, views and auth each own a stylesheet.

Hard part

A gradient clipped to text only paints inside the element box, so the calligraphic swashes were invisible. On phones, a media query that hid the plot panel left the feature unreachable.

Decision

Path-drawn SVG in its own viewBox cannot clip. Responsive rules that hide a feature are paired with a mobile presentation of it: the plot panel becomes a full-screen sheet. Module boundaries resolve imports defensively and name anything unresolved in an in-app banner.

War stories

The empty EPUB

Symptom

A full book exported as an empty EPUB, while DOCX worked.

Cause

The export picker listed project metas, which carry no text. DOCX read the open project's full blob and worked by accident.

Fix

Load the full project with getProject(id) on selection.

Lesson

A summary object and a full object with the same shape is a trap. Name them differently, or never pass one where the other is meant.

The dead plot button

Symptom

The Plot button did nothing on phones only.

Cause

A media query set the plot panel to display:none at 860px and below.

Fix

On mobile the panel becomes a full-screen sheet instead.

Lesson

A responsive rule that hides a feature must be paired with a mobile presentation of that feature, not left as an afterthought.

The invented export name

Symptom

The entire app rendered blank after a routine edit.

Cause

A named import for a function that did not exist. ES module graphs fail silently and completely on a missing named export.

Fix

Namespace imports, a candidate-name picker, try/catch wrappers, and an in-app banner naming anything unresolved.

Lesson

Defensive resolution at module boundaries turns a blank screen into a one-line diagnostic.
